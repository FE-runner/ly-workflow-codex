# context.md — impact-based-autofix-gate

软上下文：只记 artifact 之外的讨论结论与已知坑；判据正文见 proposal / design 与 delta spec。

## 关键决策与理由

1. **轮次制换成影响面制。** 轮次回答"什么时候出现"，影响面回答"该不该挡路"；只有后者能稳定区分"必须修"与"可以留"。v0.10.0 的"只修首轮"把第 2 轮的实施影响项直接判死。
2. **两族口径分写、字面统一。** `review-plan` = "影响实施"；`review-code` = "影响本次交付"（不修会导致交付物不满足目标、验收不过或引入回归）。字段名统一 `影响落地`，判据文本写成同时覆盖两者，保证六处逐字一致。
3. **`可自动修复=否` + `影响落地=是` 直接停止。** 会挡路但修不了的条目，落快照后继续等于假装处理过；停止转人工是唯一诚实选项。
4. **删除降级路径。** 影响项不能降级；不影响项本来就不参与清零。降级规则在新判据下无适用场景，保留只会制造歧义。
5. **刹车替代上界。** 同影响项相邻两轮仍在 → 停；第 3 轮起新增影响项 → 停；5 轮上限不变。影响项最多两轮必须有结论。
6. **快照零改动。** 四象限下只有 `是+是` 修完不入快照，其余三种都"未被自动修复"，现有口径天然覆盖。

## 已否决的备选

- **把首轮放宽到前 N 轮**：还是过程属性，只是把边界往后挪；N 大了重新出现"修完又出新"的尾巴。
- **`否+是` 落快照后继续**：会让"留痕"被误当成"已处置"。
- **保留降级规则作为兜底**：与"影响项必须有结论"冲突。
- **给 `review-code` 另起一套字段名**：会破坏六处判据逐字一致，进而让 `main` 与 `subagent` 两条路径的判据分叉。

## 范围边界

- **做**：新增 `影响落地` 标注与判据、四象限消费、正常清零重定义、三条新终止条件、六处判级标准、两份 review 模板、`propose.md` 两处括号定义、断言、根文档。
- **不做**：不改严重度分级、不改 `可自动修复` 判据、不改快照结构与归档/explore 口径、不加配置字段。
- `review-findings-snapshot` / `archive.md` / `explore.md` 预期零改动，由 tasks 4.3 的断言守护。

## 已知坑

- **MODIFIED 必须整块复制且 Scenario 名不可改**：`openspec validate` 会以 "omits scenario(s)" 拒绝改名。本 change 的 delta 由主 spec 原块机械抽取后改内容，避免手抄漂移。
- **REMOVED 要带 Reason + Migration**：删掉「自动修只消费首轮发现且不返工」必须同时说明替代路径，否则归档时读者找不到新规则。
- **`propose.md` 的括号定义是硬编码的旧清零定义**：它不在 `ly-review-gates` 里，容易被漏改——本轮已作为 `ly-propose-flow` 的基线波及单列。
- **未装副本不生效**：运行时读 `~/.agents/skills/` 与 `~/.codex/lyx/prompts/`，需 `lycx update` 或发版。
- **发版级别**：行为变更，下一次发版应为 0.11.0（不是 patch）。
